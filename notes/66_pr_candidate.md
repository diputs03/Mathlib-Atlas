## 1. `Mathlib/Data/Sym/Sym2.lean` (after `map_comp`)

```lean
instance : Functor Sym2 where
  map := Sym2.map

instance : LawfulFunctor Sym2 where
  map_const := rfl
  id_map x := congrFun Sym2.map_id x
  comp_map h g x := by
    show Sym2.map (g ∘ h) x = Sym2.map g (Sym2.map h x)
    rw [Sym2.map_comp (f := h) (g := g)]
    simp only [Function.comp_apply]
```

## 2. `Mathlib/Data/List/Cycle.lean` (after `map_eq_nil`)

```lean
instance : Functor Cycle where
  map := Cycle.map

instance : LawfulFunctor Cycle where
  map_const := rfl
  id_map x := by
    induction x using Quotient.inductionOn'
    show Cycle.map id _ = _
    rw [Cycle.mk''_eq_coe, Cycle.map_coe, List.map_id]
  comp_map h g x := by
    induction x using Quotient.inductionOn'
    show Cycle.map (g ∘ h) _ = Cycle.map g (Cycle.map h _)
    rw [Cycle.mk''_eq_coe, Cycle.map_coe]
    simp only [Cycle.map_coe, List.map_map]
```

(The two laws were not previously in Mathlib; they are the only new
mathematical content in this proposal.)

## Anticipated reviewer questions (answers established by the experiment)

- *Diamond with `Option` for WithBot/WithTop/OnePoint?* No active diamond:
  these are semireducible `def`s, instance search cannot see Option's
  `Functor` through them, and the branches are defeq anyway.
- *Reader-functor diamond for Stream'?* No `Functor (fun α => ℕ → α)` exists
  at this toolchain.
- *Continuity for OnePoint?* Out of scope; the data functor makes no
  continuity claim, matching how `Set`/`Multiset` functors make no order
  claims.
- *Why not `Applicative` too?* `map₂` exists for WithBot/WithTop but the
  `pure`/`seq` conventions per type are a separate design decision; proposed
  as follow-up work, not bundled here.
