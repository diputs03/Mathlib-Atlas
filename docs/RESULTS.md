# Mathlib Atlas — Results and Findings

Last updated: 2026-10-05. This document records what Atlas has actually
found, separating positive discoveries**, **audited null results, and
instrumentation boundaries. Every claim below is backed by a script
under `script/`, an independent verifier, and a case-study note under
`notes/`. The living narrative is `notes/discovery_track_consolidated.md`.

---

## 1. What "a result" means in this project

Atlas treats Lean's Mathlib as computational data. A detector's output is
only a hypothesis. A result is recorded only after:

1. the candidate is generated by a fixed, pre-registered procedure;
2. it is falsified against Lean itself (kernel-verified downstream, never
   by editing Mathlib; acceptance = exit code 0 and a zero-byte compile
   log, no `sorry`);
3. null results and false positives are classified just as carefully as
   positives.

The reusable scientific artifact is the detection → verification
process, not any single list of candidates.

## 2. Positive discoveries

### 2.1 PointwiseLift — one abstraction realized twice (`Set.image2` ≈ `Filter.map₂`)

**Finding.** The pointwise algebraic hierarchy on `Set α` and on
`Filter α` are two independent realizations of the *same* construction: a
binary lift of an operation onto a container, with the algebraic laws
derived from the lift's associativity/commutativity/identity lemmas.

- `Set` defines pointwise multiplication via `Set.image2` and proves laws
  from `Set.image2_assoc / _comm / _left_identity`.
- `Filter` defines the same thing via `Filter.map₂` with
  `Filter.map₂_assoc / _comm / _left_identity`.
- `Finset` is the *third* member of the named "pointwise monoid trio" but
  does **not** repeat the construction: its entire hierarchy is
  transferred from `Set` through the injective coercion using the generic
  `Function.Injective.*` structure-transfer API
  (`Finset.semigroup = coe_injective.semigroup _ coe_mul`, etc.).

**The gap.** There is no common abstraction over the binary-lift
primitive and its law lemmas, so `Set` and `Filter` rebuild an identical
hierarchy independently. A unifying "pointwise binary lift preserves
algebra" abstraction is a genuine design opportunity — it is recorded as
a candidate, not forced, because a kernel side condition shows the three
carriers cannot share one instance signature literally (pointwise
`Finset` operations carry `[DecidableEq α]`; `Set`/`Filter` do not).

**Evidence.** `notes/20_pointwise_lift_case.md`,
`notes/23_binary_lift_case.md`; downstream kernel check
`script/lean/20_pointwise_lift.lean` (exit 0, zero-byte log).

### 2.2 Orphan Functors — six clean, kernel-verified omissions

**Finding.** Six type constructors ship a hand-written unary lift
`map : (α → β) → F α → F β` but have no registered `Functor F`:

| Candidate | Underlying definition | `Functor` | `LawfulFunctor` |
|---|---|---|---|
| Sym2 | `Quot (Sym2.Rel α)` | compiles | laws from existing `map_id`/`map_comp` |
| WithBot | `Option α` | compiles | existing `map_id`/`map_map` |
| WithTop | `Option α` | compiles | existing `map_id`/`map_map` |
| OnePoint | `Option X` | compiles | existing `map_id`/`map_comp` |
| Stream' | `ℕ → α` | compiles | existing `map_id`/`map_map` |
| Cycle | `Quotient (IsRotated.setoid α)` | compiles | **laws proved in the experiment** |

**6/6 detector claims survived falsification.** Each instance was
compiled downstream with no elaboration tricks; probes ruled out active
diamonds (WithBot/WithTop/OnePoint are semireducible `def … := Option`,
so instance search cannot see Option's instance; no reader functor exists
at this toolchain for Stream').

The campaign also produced a false-positive taxonomy that is at least
as valuable as the positives: hypothesis-constrained lifts
(`CompactCoherentification.map`, `SummationFilter.map`), alias
constructors, quotient newtypes with unproved laws, elaboration lookalikes,
and re-export/to_additive duplicates. Each failed gate is now a named
class of "what Atlas must not abstract."

**Evidence.** `notes/66_orphan_functor_case_study.md`,
`notes/66_pr_candidate.md` (PR-shaped material, deliberately not
submitted); `script/lean/66_orphan_functor_falsification.lean`,
`66b_pi_functor_probe.lean` (exit 0 / zero-byte logs).

### 2.3 Frontier planar-combinatorics spine (kernel-verified Lean)

A complete arithmetic spine was built downstream on top of Mathlib, every
line kernel-checked: degeneracy/colorability API; planar edge bounds from
Euler; the crossing lemma; point–line incidence plus Szemerédi–Trotter
giving the unit-distance bound u(n) = O(n^{4/3}); combinatorial planar
maps (darts/α/σ/φ) with cycle-counted V/E/F and genus-zero Euler;
connectedness and χ ≤ 2; and an incidence chain complex with Betti ranks
and the algebraic χ ≤ 2. Two independent proofs of connected χ ≤ 2 were
produced. This thread is **frozen** (`notes/63_planar_frontier_freeze.md`)
with an honest layer-gap note for the topological realization
(`notes/60_genus_zero_realization_layer_gap.md`).

## 3. Audited null results — where mature Mathlib is already complete

These are not failures. Each is a measured statement that a specific,
plausible kind of hidden structure is not present at a specified
representation layer.

| Campaign | Hypothesis tested | Result |
|---|---|---|
| 67–69 | vertical generalization ladders (theorem A subsumes B, C…) | **Null.** 12,480 coarse pairs / 610 ladders are shape noise; a precise pass over 225,535 conclusion terms found only 7 expected ladders, zero unclassified |
| 70–74 | Equiv/transport gaps — isomorphisms with asymmetric API footprints | **Null.** 1,135 `Equiv` witnesses → 253 pairs; 232 coverage < 0.10, none ≥ 0.85; adjudication: 124 representation boundaries, 122 false positives, 7 intentional asymmetries, zero missing transport |
| 77–79 | cross-area exact proof-strategy signatures | **Null.** 282,971 theorem skeletons; all 40 exported coarse groups are generic coincidences; all 108 cross-area fine groups classified |

| 86–90 | approximate proof-strategy matching | **Outcome C — representation inadequate** (see §4) |

## 4. The headline meta-result: an observability boundary of mature formal mathematics

Across the proof-level campaigns, a precise and reproducible boundary was
mapped:

```
exact skeleton:   too coarse → generic noise
                  too fine   → fragmentation (the known Fin family
                               itself splits into 41 distinct keys)
approximate view: rare-token features are precise but blind to shared
                  strategy; common-token features recall slightly more
                  only under catastrophic idiom flooding
                  (550,975 matches; 99.3–99.6% of shared tokens generic)
```

Small computational/decidability proofs normalize to identical generic
shapes such as `(L KNat (A G V))` because their mathematical content
lives in the statement and in private automation, not in the
retained proof value. There is no threshold regime at which the current
structural features separate "shared mathematical strategy" from "shared
Lean proof idiom": that distinction requires statement semantics and the
*role* of each referenced lemma, which the features do not encode.

Combined with the declaration-level ledger, the conclusion is strong:

> The mature, heavily curated Mathlib corpus is almost perfectly factored
> at the declaration/type/API level. What humans have already generalized
> and refactored, structural mining cannot rediscover — beyond the two
> families in §2 (PointwiseLift; orphan Functors/option tags).

This is itself a publishable characterization of how completely a large
formal corpus has been organized, and it fixes where discovery effort
should go next.
